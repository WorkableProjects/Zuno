Zuno Mega-v1.1 Master Specification

Product: Zuno (Multi-Game Party & Habit Platform)

Version: Mega-v1.1

Status: Unified Product & Implementation Blueprint

Deployment: Static GitHub Pages; no backend required

1. Executive Overview & Architecture

Zuno v1.1 unifies multiple interactive experiences (Jeopardy, Headbands, and the new LIAR game engine) under a cohesive, highly polished dashboard ecosystem. The platform operates entirely client-side with zero backend dependencies, supporting static hosting on GitHub Pages.

Core Architecture Goals

Modular Game Engines: Each game (Jeopardy, Headbands, LIAR) runs via an independent engine while sharing a unified design language, audio system, and background animation pipeline.

Responsive Adaptive Layouts: Adapts dynamically to mobile, tablet, and desktop viewports, scaling horizontally on desktop and compactly vertical on mobile.

Unforgettable UI/UX: Features a PS5 Dashboard-inspired background system, continuous ambient motion, startup intro animations, and subtle audio feedback.

2. Global Dashboard & UI Enhancements

2.1 Dashboard & Layout Architecture

Startup Device Query: At initial launch, prompt the user to declare whether they are on mobile or desktop to configure the optimal initial layout (with options to toggle later).

Desktop Horizontal Scaling: On desktop, interfaces scale horizontally to utilize extra screen width, widening panels, cards, and content regions while preserving visual balance and legibility.

Nested Game File Interaction: Game files move from a side column to under their respective parent games when the parent game is hovered or selected. The nested game files appear smaller and chooseable directly beneath the main category card.

UI Discrepancy Fixes: App-wide audit and correction of alignment issues (e.g., aligning team names with their scores in Jeopardy).

2.2 Background Animation System ("PS5 Dashboard" Inspiration)

Continuous Independent Motion: The background animation runs continuously and independently of mouse movement, pointer velocity, or hover state. Mouse movement is never required to trigger or sustain the effect.

Glitter Layer: A subtle, moving lighter-gray background layer approximately 10% visible, behaving like a restrained glitter/shimmer effect.

Interaction Safety: All background and decorative layers sit strictly behind interactive UI elements, never blocking clicks, taps, focus states, or accessibility navigation.

Reduced Motion: Fully respect prefers-reduced-motion settings by reducing or disabling non-essential decorative animations when enabled.

2.3 Audio System (public/music)

Asset Location: All audio assets reside in the project root directory at public/music.

Subtle Hover Feedback: Audio files are used exclusively as very subtle, short, quiet hover sounds. Avoid loud or constant playback.

Looping & Fading: Music loops support smooth fade-in and fade-out transitions.

Mute Toggle & Resilience: Provide a visible, accessible mute toggle with clear state feedback. The app remains fully functional and resilient if audio files are missing or muted.

2.4 Animation & Polish (Dutch Additions)

Startup Intro Animation: Each session/app launch features an elegant introductory animation where elements sequence in smoothly.

Dynamic Backgrounds: Backgrounds evolve dynamically (e.g., introducing richer secondary elements when hovered or active for extended periods).

Transition Polish: Smooth page and element transition animations across all views.

5. LIAR Game Engine (New Addition)

LIAR is a social guessing game based on Two Truths and a Lie, built as a first-party Zuno party-game engine.

5.1 Core Gameplay Rules

Three Statements: Each storyteller provides exactly three statements: two truths and one lie.

Follow-up Questions: Every statement must include at least one follow-up question prompt to guide group investigation.

Private Lie Marker: The storyteller privately marks which statement is the lie before presenting them to the group. The lie indicator remains hidden from the public view until the reveal phase.

Discussion & Voting: Non-storyteller players ask questions, discuss, and submit private votes. Votes remain hidden until voting closes.

Scoring: Optional scoring awards 1 point to players who correctly guess the lie, and 1 point to the storyteller for each player who votes for a truthful statement (deception score). Casual play without scoring is fully supported.

Player Count: Supports 3 to 10 players by default.

5.2 LIAR File Format & Validation

Uses Zuno's .zuno.json format envelope (schemaVersion: 1, gameType: "liar").

Validates prompt decks, settings ranges, and turn constraints (exactly 3 statements, 1 lie, at least 1 question per statement).

Strings are treated as untrusted plain text.

6. Cross-App Consistency & Deployment

Static Deployment: Fully client-side execution compatible with GitHub Pages repository subpaths.

Accessibility: Semantic HTML, visible keyboard focus rings, high-contrast text ratios, and prefers-reduced-motion support.

Testability: All game rules, validation schemas, and UI flows pass automated unit tests and build checks (npm run build, npm test).
